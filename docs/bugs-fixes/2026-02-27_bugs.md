## BUG-9: No way to delete workout sessions from history
**Status:** FIXED (2026-02-27)
**Priority:** P1 (high)
**Reported:** 2026-02-27
**Screen:** Session Detail (`SessionDetailScreen.kt`)

### Problem
Users cannot delete erroneous or test workout sessions from their history. No delete functionality exists at any layer (DAO, repository, or UI).

### Root Cause
Delete methods were never implemented. FK cascade chain was already set up correctly (session → exercises → sets cascade, personal_records set null).

### Fix
- Added `deleteById(id)` to `WorkoutSessionDao`
- Added `deleteSession(id)` to `WorkoutSessionRepository` + impl
- Added trash icon button in SessionDetailScreen TopAppBar
- Added confirmation dialog with MVI flow (RequestDelete/ConfirmDelete/DismissDelete)
- Navigates back after successful deletion

## BUG-10: Cannot undo a completed set during active workout
**Status:** FIXED (2026-02-27)
**Priority:** P1 (high)
**Reported:** 2026-02-27
**Screen:** Active Workout (`WorkoutScreen.kt`)

### Problem
After marking a set as "done" with wrong weight/reps, the set becomes read-only. No way to revert and correct the mistake.

### Root Cause
`handleCompleteSet()` only handled the complete direction. No uncomplete handler existed. SetRow UI already had "Mark incomplete" accessibility text but no backend handler.

### Fix
- Added `uncompleteSet(setId)` to `WorkoutSetDao` (clears actuals + status in Room)
- Added `uncompleteSet(setId)` to `WorkoutSessionRepository` + impl
- Added `UncompleteSet` intent and `handleUncompleteSet()` handler in WorkoutViewModel
- Toggle logic: `handleCompleteSet()` detects already-completed sets and delegates to uncomplete
- UX: reverts to IN_PROGRESS, keeps weight/reps pre-filled for editing, re-expands exercise card, cancels rest timer

### Files
- `core/database/dao/WorkoutSetDao.kt`
- `core/domain/repository/WorkoutSessionRepository.kt`
- `core/data/repository/WorkoutSessionRepositoryImpl.kt`
- `feature/workout/active/WorkoutIntent.kt`

## BUG-11: Weight/reps input too slow with +/- stepper buttons
**Status:** FIXED (2026-02-27)
**Priority:** P1 (high)
**Reported:** 2026-02-27
**Screen:** Active Workout (`WorkoutScreen.kt`)

### Problem
The `[ - 20 + ]` stepper requires too many button presses to change weight significantly. Mid-workout data entry is frustratingly slow.

### Root Cause
Design decision — stepper was the original input method. Not suitable for real-world gym use.

### Fix
Two new input methods:
1. **Single tap** → opens simplified bottom sheet with large numeric text field + keyboard (replaced +/- stepper). Auto-selects text for immediate typing. Snaps weight to 0.5kg increments.
2. **Long-press + drag up/down** → continuous value adjustment directly on the set row. 2.5kg per ~30dp for weight, 1 rep per ~30dp for reps. Haptic feedback on each step.

Existing `NumberInput` component preserved for PlanReview screen. Changes isolated to `NumberInputSheet` (simplified) and `SetRow` ValueCell (new drag gesture). Drag callbacks default to null — SessionDetail and PlanReview screens unaffected.

### Files
- `core/ui/component/NumberInputSheet.kt`
- `core/ui/component/SetRow.kt`
- `feature/workout/active/components/ExerciseCard.kt`
- `feature/workout/active/WorkoutScreen.kt`
